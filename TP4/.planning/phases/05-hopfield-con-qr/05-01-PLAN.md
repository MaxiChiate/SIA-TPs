<objective>
Build the one genuinely new piece of engine this phase needs that does NOT run the network on the QR and is NOT part of the (not-yet-frozen) pre-registration: the pseudo-inverse learning rule in the existing C core and its float-tolerant numpy twin (the remedy for HOP-06, D-06/D-07). (The PNG to pm-one converter, the preparation half of HOP-04, is split into the parallel wave-1 plan 05-06 to keep this plan inside the per-plan context budget; the two plans share no files and neither depends on the other.)

Purpose: the pseudo-inverse over a real-valued W is the one genuinely new architecture in this phase (the Phase 4 core assumed an exact integer W everywhere). Proving it end-to-end now - config to C binary to CSVs to independent numpy agreement - on a small synthetic fixture catches the float-W accounting (energy increment with a non-zero diagonal, tolerant fixed-point test, singular-Gram handling) before any QR run or figure is built on top of it.

Output: hopfield_pinv in the C core wired through rule="pinv" and a float-aware analysis/hopfield.py, both proven on a small synthetic fixture under the sanitizers.

Flagged assumptions (surfaced, not resolved - no phase SPEC Edge Coverage):
- HOP-06 (singular Gram): a rank-deficient stored set has no pseudo-inverse; the rule returns 0 and the model aborts with a message rather than inventing weights.
</objective>
