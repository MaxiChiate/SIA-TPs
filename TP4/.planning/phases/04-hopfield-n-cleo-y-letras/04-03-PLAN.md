## Phase Goal

**As a** student, **I want to** validate a Hopfield core on four 5x5 letters, **so that** I understand recovery, energy, capacity and spurious states before moving to QR codes.

<objective>
Draw a new 5x5 alphabet without running any network code on it, pre-register how the letters are chosen and how every Hopfield experiment on them runs, have the user approve the glyphs one by one and the rule, and freeze everything in one commit before the network touches the letters. Task 1 is the tracer: the new alphabet through the converter, the integer selection with the tie-breaks of D-04b, the rule text and the guard; Task 2 is the user's approval checkpoint (glyphs, rule text, design); Task 3 is the user's pathspec commit. The tie-breaks and the p range are already settled in CONTEXT (D-04b, D-05), so no tie-break choice is put to the user.

Purpose: D-03, D-04 and D-04b (one-way): "chosen beforehand" is only true if the alphabet, the rule and the tie-breaks had no network quantity computed or shown on them before this commit (the research draft did, so it is discarded), and if the commit exists before plan 04-05 runs anything on the letters.
Output: datos/letters/alphabet_5x5.txt, real-alphabet tests in analysis/tests/test_letters.py, analysis/hopfield_select.py, analysis/tests/test_hopfield_select.py, deliverables/04-hopfield-letras.md (title and section 3), and the user's rule commit.
</objective>
